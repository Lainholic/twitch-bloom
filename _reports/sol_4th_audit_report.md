**4차 정적 평가: 74/100. 제한된 해커톤 시연은 CONDITIONAL GO, 공개 방송용 최종 출시와 24/7 OBS 송출은 NO-GO입니다.** 브라우저·테스트 통과 내역은 이번 환경에서 직접 실행하지 못했으므로 별도 미검증 주장으로 구분합니다.

## 4. 주요 잔존·신규 결함

### 4.1 P1 — 상태는 7종 랜덤이지만 화면 표현은 7종 균등이 아님

**증거:** Renderer `syncTrash()`의 sprite 선택 분기에는 `paper` 대응이 없습니다. 따라서 Garden이 `paper`를 선택하면 다음 fallback에 진입합니다.

```javascript
const pool = [
  'pizza', 'crushedCan', 'bananaPeel', 'poisonMushroom',
  'fishbone', 'coffeecup', 'battery', 'appleCore', 'clover', 'potion'
];
spriteKey = pool[Math.floor(Math.random() * pool.length)];
```

결과:

- 상태는 `paper`인데 화면에는 물약·배터리·사과 등이 표시될 수 있습니다.
- 7종 풀에 없는 시각적 종류도 동적 투척으로 등장합니다.
- 균등 난수 선택을 가정하면 **동적 투척의 물약 sprite 확률은 `1/7 + (1/7 × 1/10) = 11/70`**, 약 15.7%입니다. 상태상의 물약 확률 약 14.3%와 다릅니다.

이는 **수학적 코드 분석이며 실측 빈도는 아닙니다.**

**텍스트 수정안:** `paper`의 명시적 sprite 대응을 추가하고, 알려진 상태 타입에는 다른 종류를 무작위로 대체 표시하지 않도록 하십시오. 종이 에셋이 없다면 실제 기존 에셋을 확인한 뒤 표현 정책을 결정해야 합니다.

### 4.2 P1 — 웃음 외 전역 생성·효과 예산 없음

Garden `apply()` 투척 분기:

```javascript
if (trashItems.length >= trashCapacity) trashItems.shift();
...
trashItems.push(trash);
```

이는 **보유 개수 제한**이지 생성률 제한이 아닙니다. 서로 다른 사용자의 입력은 계속 수락됩니다.

HTML `handleEvent()`는 수락된 입력마다 다음 전체 동기화를 수행합니다.

```javascript
rendererApp.syncFlowers(garden.getFlowers());
rendererApp.syncTrash(garden.getTrash());
```

`emitEffect: false`인 웃음도 이 경로를 실행합니다. 채팅 DOM 추가는 `res.accepted` 검사 밖에 있어 거절된 입력도 처리됩니다.

Renderer 효과별 명시적 파티클 생성량:

- 물: 덩굴 효과 6개 + 일반 효과 35개
- 햇빛: 7개 + 36개
- 청소: 40개
- 새 꽃·쓰레기 제거·착지 효과는 별도

**판정:** 실제 프레임 저하 정도는 미검증이지만, 입력량에 비례한 작업량을 제어하는 전역 예산 부재는 확인됩니다. 공개 방송 차단 사유입니다. 다만 **부하 실측 없이 확정 런타임 크래시와 같은 P0로 단정하지는 않습니다.**

**텍스트 수정안:** 투척 토큰 버킷, 공유 효과 예산, 프레임당 상태 동기화 병합, 채팅 표시 업데이트 상한을 적용하십시오.

### 4.3 P1 — 빈 청소 반복 효과 경로 유지

Garden `apply()` 청소 분기:

```javascript
if (trashItems.length === 0) {
  return { accepted: true, command, owner, cleanedCount: 0 };
}
```

이 경로에는 `trackUser()`가 없습니다. HTML은 수락된 청소라면 다음을 무조건 호출합니다.

```javascript
audio.playClean();
rendererApp.triggerCleanEffect();
```

신규 사용자 또는 쿨다운이 만료된 사용자는 빈 정원을 반복 청소해 계속 효과를 발생시킬 수 있습니다.

테스트도 빈 청소와 같은 시각에 같은 사용자의 투척을 수락하도록 기대해 이 동작을 고정합니다.

**텍스트 수정안:** 빈 청소를 무효 동작으로 반환하거나 `emitEffect: false`를 반환해 HTML이 효과를 생략하도록 하십시오. 시도 쿨다운 정책도 명시해야 합니다.

### 4.4 P1 — FIFO 퇴출에 쿨다운 기록까지 소실

`trackUser()` 상대 **L2–L7**:

```javascript
if (!stats.userActions.has(user)) {
  if (stats.userActions.size >= MAX_USERS) {
    const oldestUser = stats.userActions.keys().next().value;
    stats.userActions.delete(oldestUser);
  }
```

기존 사용자 재접근 시 Map 순서를 갱신하지 않으므로 LRU가 아닙니다. 기록이 퇴출되면 `lastAction`과 `lastLaugh`도 함께 사라져 사용자 쿨다운을 우회할 수 있습니다.

또한 두 시각의 초기값이 `0`이므로 테스트 시간축에서는 **아직 실행하지 않은 행동의 첫 입력도 다른 행동 기록 때문에 차단될 수 있습니다.**

**텍스트 수정안:** 미실행 시각을 `null` 등으로 구분하고 통계 퇴출과 쿨다운 보존 정책을 분리하십시오.

### 4.5 P1 — 기존 객체 리사이즈 좌표 고착

Renderer의 resize 핸들러와 `renderer.setSize()`는 캔버스·클로저 크기를 갱신합니다. 그러나:

- `syncFlowers()`의 기존 record 분기는 `x`, `y`를 갱신하지 않습니다.
- `syncTrash()`는 기존 record의 `x`, `targetY`를 재계산하지 않습니다.
- resize 핸들러에도 기존 객체 재배치가 없습니다.

**판정:** 크기 변수 동기화는 해결됐지만 기존 객체의 반응형 배치는 미해결입니다.

**텍스트 수정안:** 정규화 위치·바닥 기준 오프셋을 보존하고 크기 변경 시 착지 목표와 정지 객체 위치를 함께 재계산하십시오.

### 4.6 P1 — 공개 반환값 참조 누출

Garden:

```javascript
getFlowers: () => [...flowers.values()].map(f => ({ ...f })),
```

이 복사는 중첩 `traits`를 분리하지 않습니다. `apply()`도 `flower`, `trash` 내부 객체를 직접 반환합니다.

```javascript
return { accepted: true, command, owner, flower, isNew };
return { accepted: true, command, owner, trash };
```

**판정:** 외부 호출자가 내부 상태를 변경할 수 있습니다. 다만 현재 자료만으로 원격 공격 경로가 입증된 것은 아닙니다.

**텍스트 수정안:** 모든 공개 꽃 DTO에서 `traits`까지 복사하고 `apply()` 반환 객체도 내부 상태와 분리하십시오.

### 4.7 P1 — IRC 일반 NOTICE도 영구 종료

IRC `open()`의 메시지 처리:

```javascript
if (message.command === 'NOTICE' ||
    ['464', '465', '403', '474'].includes(message.command)) {
  stopped = true;
  ...
  ws.close();
  return;
}
```

일반 안내와 인증 실패를 구분하지 않습니다. `onChat()` 예외 격리도 없어 콜백이 던지면 현재 메시지 배치 처리가 중단될 수 있습니다.

**텍스트 수정안:** NOTICE의 태그·내용에 따라 상태를 분류하고, 개별 채팅 콜백 예외가 후속 메시지 처리를 막지 않게 하십시오.

### 4.8 P2 — 렌더 할당·파서·시간 단위 문제

- `spawnParticle()` 상대 **L2–L3**는 객체를 계속 생성합니다. `> 180` 검사이므로 정상 경로 최대 길이는 **181개**입니다.
- `renderFrame()`의 황금 꽃 파티클은 프레임별 확률이라 FPS에 생성량이 비례합니다. 황금 표시 자체는 `growth >= 3`으로 일반 성장에서도 도달합니다.
- `!clean 💧`는 물로 파싱됩니다.
- `lollipop`은 부분 문자열 `lol` 때문에 웃음으로 파싱됩니다.
- VS16 없는 `☀`는 햇빛으로 처리되지 않습니다.
- capacity·cooldown 설정의 유효성 검사가 없습니다.
- HTML `animate()`는 밀리초인 `now`를 `drawMockGame(now)`에 전달하지만 내부 `Math.sin(time * 6)` 등은 초 기반 표현으로 보입니다. 애니메이션 속도 의도 확인이 필요합니다.

**덩굴 설정 배열의 프레임별 생성 제거는 인정합니다. “전체 렌더 GC 제로”로 확대해서 보고하면 안 됩니다.**

## 5. 별도 통합 위험 — 결산 카드

HTML은 다음을 실행합니다.

```javascript
rendererApp.scene.add(summaryCard.group);
```

그러나 Renderer의 `scene.add()`는 배열에 객체를 저장할 뿐이며:

```javascript
render: () => { renderFrame(); },
```

실제 렌더 경로는 `scene.children`을 순회하지 않습니다.

**확인된 사실:** 이 Renderer는 추가된 scene 객체를 직접 그리지 않습니다.

**미확인 사항:** `summary-card.mjs`가 DOM·별도 캔버스를 통해 독립적으로 표시하는지는 알 수 없습니다. 따라서 카드가 안 나온다고 확정하지는 않지만, **결산 카드 표시와 PNG 저장은 출시 전 필수 통합 검증 대상**입니다.

## 6. 12개 테스트의 증명 범위

물약 테스트는 두 입력이 `trash`로 처리되고 반환 타입이 7종 집합에 속하는지만 확인합니다.

```javascript
assert.ok([...].includes(resPotion.trash.type));
```

따라서 다음은 증명하지 못합니다.

- 물약 확정 투척 분기가 다시 생겼는지
- 7종이 모두 선택 가능한지
- 선택 경계가 올바른지
- 화면 sprite와 상태 타입이 일치하는지

물약만 항상 반환해도 해당 테스트는 통과할 수 있습니다.

**권장 회귀 테스트:**

1. 제어 가능한 난수로 7개 선택 구간을 각각 검사.
2. 물약·포션·비료·일반 쓰레기에 동일한 선택 규칙 적용 확인.
3. Renderer 생성 → 꽃 동기화 → render → 이름표 ON/OFF.
4. `paper` 포함 상태 타입별 sprite 대응.
5. 빈 청소 반복·사용자 기록 퇴출 후 쿨다운.
6. resize 후 기존 꽃·쓰레기 좌표.
7. 일반 NOTICE와 인증 실패의 서로 다른 처리.
8. 브라우저 버튼·결산 카드·PNG·투명 OBS 모드 통합 검증.
