### 4.1 P0 — `nameplatesEnabled` 미선언으로 렌더·버튼 실행 오류

**증거 A: `drawNameplate()` L1–L2**

```javascript
function drawNameplate(text, cx, cy, isGold) {
  if (!nameplatesEnabled || !text) return;
```

**증거 B: `toggleNameplates()` L1–L3**

```javascript
function toggleNameplates(enabled) {
  nameplatesEnabled = (enabled !== undefined) ? enabled : !nameplatesEnabled;
  return nameplatesEnabled;
```

첨부 Renderer 전체에 `nameplatesEnabled` 선언이 없습니다. HTML의 `namesVisible`은 별개 변수입니다.

제공 코드 기준 예상 결과:

- 꽃이 하나 생기면 `renderFrame()`이 `drawNameplate()`에 진입하여 **`ReferenceError`**를 발생시킵니다.
- 꽃이 없어도 이름표 버튼을 누르면 오류가 발생합니다.
- HTML은 프레임 시작 시 다음 `requestAnimationFrame()`을 예약하므로, 오류 후에도 **후속 프레임에서 반복 오류가 발생할 수 있습니다.**

이는 실행 실측이 아니라 **선언 누락과 호출 경로로 확인한 정적 실행 결함**입니다. 현재 12개 테스트는 Renderer를 import하지 않아 잡지 못합니다.

**텍스트 수정안:**

```javascript
// createRenderer() 내부 상태 선언부
let nameplatesEnabled = false;
```

기존 ON 동작을 유지하려면 `true`와 HTML 초기 표기를 맞추십시오. 방송 안전 기본값은 OFF를 권합니다.

### 4.2 P0 — 웃음 외 전역 군중 제어는 여전히 없음

**Garden 투척 분기:**

```javascript
if (trashItems.length >= trashCapacity) trashItems.shift();
...
trashItems.push(trash);
```

다수 고유 사용자가 동시에 투척하면 모두 수락합니다. 100개 상한은 **현재 보유량**만 제한하며 생성률·교체율은 제한하지 않습니다.

**HTML `handleEvent()`:**

```javascript
rendererApp.syncFlowers(garden.getFlowers());
rendererApp.syncTrash(garden.getTrash());
```

이 동기화는 `emitEffect: false`인 수락된 웃음에도 실행됩니다. 효과가 초당 한 번이어도 **각 메시지의 배열 복사·Set 생성·전체 상태 순회·DOM 채팅 갱신 비용은 제한되지 않습니다.**

또한 물·햇빛·청소는 수락될 때마다 효과를 호출합니다.

- 물: `growVines()` 6개 + 추가 35개 파티클
- 햇빛: 7개 + 추가 36개
- 청소: 추가 40개

파티클 보유량 상한이 생성 작업량을 제한하지는 않습니다.

**따라서 “수천 명 동시 웃음에서 효과만 1초당 한 번”은 맞지만, “수천 명 입력 전체가 안전하게 처리된다”는 입증되지 않았습니다.**

**텍스트 설계안:**

1. 투척 전역 토큰 버킷 및 포화 거절 정책.
2. 물·햇빛·청소의 공유 효과 예산.
3. 상태가 변하지 않는 웃음은 꽃·쓰레기 재동기화 생략.
4. 상태 변경 동기화는 프레임당 한 번으로 병합.
5. 채팅 표시 업데이트에도 처리량 상한 적용.

### 4.3 P1 — 사용자 상한은 FIFO이며, 쿨다운까지 함께 퇴출됨

**`trackUser()` L2–L7:**

```javascript
if (!stats.userActions.has(user)) {
  if (stats.userActions.size >= MAX_USERS) {
    const oldestUser = stats.userActions.keys().next().value;
    stats.userActions.delete(oldestUser);
  }
```

기존 사용자의 활동 시 `delete()` 후 `set()`으로 순서를 갱신하지 않습니다. 따라서 **최근 활동 여부와 관계없이 최초 삽입 순서로 퇴출**됩니다.

재현 가능한 논리 경로:

1. 사용자 A가 웃음.
2. 이후 500명의 신규 사용자가 유입되어 A 기록 퇴출.
3. A가 1,500ms 이내 다시 웃음.
4. 기록이 없으므로 사용자별 제한 통과.

전역 효과 제한은 유지되지만, 사용자별 기여 제한은 우회됩니다. 일반 행동 쿨다운도 같은 문제가 있습니다.

추가로 `lastLaugh: 0`, `lastAction: 0` 초기값 때문에 테스트 시간축에서는:

- `!water`를 시각 0에 한 사용자의 **첫 웃음**이 시각 500에서 차단될 수 있음.
- 시각 0에 처음 웃은 사용자의 **첫 물주기**도 시각 500에서 차단될 수 있음.

실제 현재 epoch 시각에서는 초기 0으로 인한 현상이 드러나기 어렵지만, 독립 쿨다운 계약과 테스트 가능성 측면에서는 결함입니다.

**수정안:** 행동별 미실행 시각을 `null` 등으로 구분하고, 쿨다운 기록 보존 정책과 통계 기록 퇴출 정책을 분리하십시오. LRU로 바꾸더라도 **퇴출을 이용한 쿨다운 우회 정책**은 별도 해결해야 합니다.

if (trashItems.length === 0) {

### 4.5 P1 — 리사이즈는 캔버스만 수정, 기존 객체는 옛 좌표 유지

### 4.6 P1 — 렌더 루프 할당 제로 주장은 반증됨

**`spawnParticle()` L1–L3:**

```javascript
function spawnParticle(...) {
  if (particles.length > 180) particles.shift();
  particles.push({ x, y, vx, vy, color, size, life: 0, maxLife, shape });
```

`renderFrame()`은 황금 꽃마다 프레임 기반 확률로 이 함수를 호출합니다.

```javascript
if (record.isGold && Math.random() < 0.25) {
  spawnParticle(...);
}
```

따라서:

- 렌더 중 명시적인 객체 할당이 남아 있음.
- 파티클 발생량은 FPS에 비례함.
- 파티클 정상 경로의 최대 길이는 **181개**임.
- `measureText()` 등 브라우저 내부 할당까지 제로라고 보장할 수 없음.

덩굴 설정 객체 48개의 반복 할당 제거는 인정하지만, 보고 문구는 **“덩굴 설정의 프레임별 할당 제거”**로 한정해야 합니다.

**수정안:** 시간 기반 파티클 발생률, 상한 도달 시 생성 생략, 필요 시 풀링. GC 개선 효과는 프로파일링으로 평가하십시오.

### 4.7 P1 — 불변 상태 경계는 아직 부분적

**`getFlowers()`는 중첩 `traits` 참조 유지:**

```javascript
getFlowers: () => [...flowers.values()].map(f => ({ ...f })),
```

**`apply()`는 내부 객체 직접 반환:**

```javascript
return { accepted: true, command, owner, flower, isNew };
return { accepted: true, command, owner, trash };
```

외부 호출자가 반환된 객체를 변경하면 Garden 내부 상태도 바뀔 수 있습니다. HTML은 Garden을 `window.twitchBloom`으로 공개합니다. 이것만으로 원격 공격 경로가 입증되는 것은 아니지만, 상태 소유권 계약은 깨져 있습니다.

**수정안:** 모든 공개 DTO에서 꽃 `traits`까지 복사하고, `apply()`의 반환 객체도 분리하십시오.

### 4.8 기존 IRC·파서 결함 잔존

- **모든 NOTICE가 영구 종료:** 일반 안내와 인증 실패 구분 없음.
- **`onChat` 예외 격리 없음:** 콜백 오류가 현재 배치 처리를 중단할 수 있음.
- **동기 전체 배치 처리:** 처리량 예산 없음.
- **명령보다 이모지가 우선:** `!clean 💧`는 물로 처리됨.
- **영문 부분 문자열 웃음:** `lollipop`이 웃음으로 처리됨.
- **VS16 없는 햇빛 이모지:** `☀` 미지원.
- **설정 유효성 검사 없음:** `Infinity` 등의 capacity는 상한 정책을 무력화할 수 있음.

`gold`가 투척으로 분류되는 것은 이번 지시상 의도된 동작으로 보입니다. 다만 도달 불가 `gold` 분기·통계·효과 연결은 정리 대상입니다.

또한 HTML 정규화가 `!물약`을 `!trash`로 바꾸므로 Garden의 물약 타입 강제 지정이 사라집니다. **단위 테스트의 직접 Garden 호출에서는 물약이 보장되지만 실제 UI 경로에서는 무작위 쓰레기 타입이 됩니다.**

## 5. 12개 테스트의 실제 의미

첨부 파일에서 **`test()` 선언 12개는 확인했습니다.** 실행 성공 여부는 확인하지 못했습니다.

신규 테스트가 확인하도록 작성된 내용:

- 동일 사용자 웃음 차단.
- 다른 사용자 웃음의 전역 효과 간격.
- 520명 입력 후 사용자 기록 상한.
- `topUsers` 반환 객체 복사.

그러나 다음은 검증하지 않습니다.

| 필수 회귀 테스트 | 요구 결과 |
|---|---|
| Renderer 생성 → 꽃 추가 → render | 예외 없음 |
| 이름표 버튼 ON/OFF | 예외 없음, 표기 일치 |
| 1초 1,000명 웃음의 HTML 처리 | 효과 제한뿐 아니라 동기화·DOM 처리량 제한 |
| 기록 퇴출 후 동일 사용자 재입력 | 정한 쿨다운 정책 준수 |
| 빈 정원 동일 사용자 청소 반복 | 효과 폭주 없음 |
| 대량 투척·물·햇빛 | 전역 생성·효과 예산 준수 |
| `setSize()`·window resize | 기존 객체 위치·착지 목표 일관성 |
| 공개 반환값 모든 경로 변조 | 내부 상태 변경 없음 |
| 일반 NOTICE와 인증 실패 | 서로 다른 올바른 상태 전이 |
| HTML 물약 버튼 | 의도한 타입 유지 |
| OBS 부하·장기 실행 | 프레임 시간·입력 지연·GC 이후 힙 기준선 기록 |

특히 메모리 테스트는 `<= 500`만 검사하므로, 정확한 500개 유지·퇴출 대상·LRU·쿨다운 보존은 입증하지 않습니다.

## 6. 최종 권고

### 해커톤 시연 전 최소 조건

1. `nameplatesEnabled` 선언 및 UI 초기 상태 일치.
2. 브라우저에서 물·햇빛·쓰레기·청소·웃음·이름표 실제 실행.

5. 시연 입력량을 제한하고 미검증 성능 보장을 발표에서 제외.

이를 확인하면 **제한된 해커톤 시연은 CONDITIONAL GO**로 재평가할 수 있습니다.

### 공개 방송 전 추가 조건

- 모든 명령의 전역 예산.
- 상태 동기화와 DOM 처리 병합·상한.

- 기존 객체 리사이즈 처리.
- IRC 일반 NOTICE·예외 처리.
- 실제 OBS 부하 및 장기 힙 검증.
